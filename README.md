# 🎄 THE CHRISTMAS AFTERPARTY: SKY VILLAGE

구름 위에 떠 있는 크리스마스 마을을 여러 방문자가 각자의 아바타로 함께 걸어 다니는 3D 멀티플레이 웹사이트.
이 저장소는 **첫 번째 프로토타입(Phase 1–3)** 입니다: 3D 하늘섬 마을 + 아바타 이동 + 실시간 멀티플레이.

| | |
|---|---|
| 클라이언트 | React 19 · TypeScript · Vite 7 · three.js · React Three Fiber 9 · drei |
| 서버 | Node 22 · Colyseus 0.16 (`@colyseus/core`, ws transport) |
| 공유 | `packages/shared` — 월드 레이아웃·충돌·프로토콜 (서버/클라이언트 동일 코드) |
| 에셋 | **없음.** 모든 모델과 텍스처는 코드(절차적 지오메트리 + 캔버스 텍스처)로 생성 |

## 실행

```bash
npm install
npm run dev          # 서버(2567) + 웹(5173) 동시 실행
```

브라우저 두 개(또는 시크릿 창)에서 <http://localhost:5173> 을 열고 닉네임을 입력하면 같은 파티룸에서 서로의 아바타가 보입니다.
HUD의 **💌 초대 링크**를 복사해 보내면 같은 방으로 입장합니다(`?room=<id>`). 방은 16명이 차면 새 방이 자동으로 열립니다.

- 조작: `WASD`/방향키 이동 · 마우스 드래그 시점 · 휠 줌 · `E` 상호작용 / 모바일: 왼쪽 조이스틱 + 화면 드래그
- 같은 네트워크의 폰에서: `npm run dev`는 `--host`로 열려 있으니 `http://<PC-IP>:5173` (서버는 접속한 호스트의 2567 포트로 자동 연결)
- 다른 서버 주소: `VITE_SERVER_URL=wss://… ` ([.env.example](.env.example))
- 그래픽 품질: HUD 선택(높음/보통/낮음). 모바일은 자동으로 보통/낮음. URL `?q=low` 로 강제 가능
- 프로덕션 빌드: `npm run build` (웹), `npm run start:server`

## 구조

```
apps/web      3D 사이트 (src/game: world · buildings · props · avatar · controls, src/net, src/ui)
apps/server   Colyseus PartyRoom (권위 서버)
packages/shared  world.ts(레이아웃+충돌) · protocol.ts · constants.ts · sanitize.ts + 테스트
assets/       (비어 있음) 향후 GLB/텍스처 원본 — 컴포넌트를 GLB로 교체할 수 있도록 설계
docs/DESIGN_ANALYSIS.md   레퍼런스 이미지 분석과 건축 개선 내역
tests/e2e     브라우저 E2E (두 브라우저 멀티플레이, 모바일 터치)
```

### 핵심 설계

1. **충돌 코드는 하나.** `world.ts`의 보행 영역(원·사각 합집합)과 장애물(원·회전 박스)을 서버 검증, 클라이언트 예측, 3D 배치가 모두 사용합니다. 장식(창·지붕·가랜드)은 충돌에 참여하지 않습니다.
2. **서버 권위 이동.** 클라이언트는 *위치가 아니라 입력 방향*만 보냅니다. 서버가 `WALK_SPEED`로 적분 → 속도 위조·순간이동·벽/절벽 통과가 구조적으로 불가능합니다. 입력은 길이 1로 클램프, 초당 40건 제한, 400 ms 무입력 시 정지, 비정상 위치는 광장으로 복귀(`reset`).
3. **클라이언트 예측 + 보정.** 내 아바타는 즉시 반응(같은 이동 코드), 서버와 1.2 m 이상 벌어지면 부드럽게 보정, 3 m 이상이면 스냅.
4. **델타 스냅샷.** 15 Hz, *움직인 플레이어만* 전송(정지 시 트래픽 0). 다른 사람의 아바타는 120 ms 지연 보간으로 렌더링 — 네트워크 수신과 렌더 루프는 분리(React 상태 미사용, 입·퇴장 때만 리렌더).
5. **재접속.** 비정상 끊김 시 서버가 20초간 아바타를 유지(`allowReconnection`), 클라이언트는 같은 세션으로 자동 재접속하고 HUD에 상태를 표시합니다. 창이 만료되면 "다시 입장" 안내.
6. **확장 지점.** `game/events.ts`(이벤트 버스 + `Interactable` 레지스트리)와 `ZONES`(7개 구역의 위치·문 앞 좌표·상태), `EXPANSION_SLOTS`(예약된 공중섬과 다리 경로)가 Phase 5 기능의 연결점입니다. 문 앞에 서면 "준비 중" 안내가 뜨는 것이 현재 구현된 상호작용입니다.
7. **성능 장치.** 정적 메시 병합(`world/Batch.tsx`: 건물 하나 ~60개 부품 → ~8 드로우), 글로우·조명 줄을 월드 단위 인스턴스 드로우로 통합, 아바타를 정점색 베이킹으로 7 메시/명, 환경 애니메이션은 GPU 셰이더, 품질 프리셋(그림자·DPR·눈 입자·구름).

## 현재 구현 범위

**Phase 1 — 마을 (완료)** 하늘섬(암석 하부·폭포·난간), 스타라이트 광장, 거대 트리, 동화풍 건물 4채(초대장 우체국·캔디 마켓·벨벳 볼룸·달빛 탑) + 소원 오두막, 아치 다리 1개 + 작은 공중섬, 구름바다, 눈, 가로등·벤치·눈사람·선물·무대, 예약된 확장 섬 3개.
**Phase 2 — 이동 (완료)** 귀여운 아바타(대기/걷기 애니메이션, 닉네임), WASD·모바일 조이스틱, 3인칭 카메라(건물에 막히면 당김, 트리가 가리면 페이드), 건물/소품 충돌, 절벽 경계, 다리 이동.
**Phase 3 — 멀티플레이 (완료)** 게스트 입장(닉네임·아바타 색), 세션 ID, 방당 16명, 위치·회전 동기화+보간, 입·퇴장 반영, 재접속, 서버 검증, 초대 링크, 연결 상태 표시.
**미구현 (Phase 4–5):** 낮/밤 전환, 아바타 의상 교체, 파티 홀·소원 숲·마켓·미니게임·AI 포토부스·카운트다운 이벤트(문 앞 "준비 중" 안내만 있음), 효과음/음악, 감정 표현.
AI 포토부스: 요청대로 **이미지 API 호출·사진 저장 없음**. 향후 설계 시 동의/삭제 정책, 서버측 API 키, 횟수 제한을 고려해야 합니다.

## 알려진 한계 / 확인하지 못한 것 (솔직한 보고)

- **실제 GPU·실제 폰에서의 프레임레이트는 측정하지 못했습니다.** 테스트 환경은 소프트웨어 렌더링(저해상도에서 ~20 fps)이라 fps 수치는 의미가 없습니다. 수치로 확인한 것은 드로우콜/삼각형뿐입니다. **삼각형 25만+는 저사양 모바일에는 무거울 수 있고**, 품질 프리셋은 그림자·해상도·입자·구름을 줄이지만 지오메트리 LOD는 아직 없습니다(Phase 4 최우선 과제).
- iOS Safari / 실제 터치 기기, 서로 다른 PC 간 실망(RTT 100 ms+) 환경은 테스트하지 않았습니다. 보간 지연(120 ms)과 보정 임계값은 합리적 값이지만 실측 튜닝이 필요합니다.
- **Rapier는 사용하지 않았습니다(의도적 변경).** 서버가 동일한 충돌을 실행해야 하고, 이번 범위(보행 가능 영역 + 원/박스 장애물)에는 경량 2D 코드가 더 검증하기 쉬웠습니다. 동적 물체/중력/점프가 필요해지면 Rapier 도입을 재검토하세요.
- Colyseus는 안정 라인인 **0.16**으로 고정했습니다(최신 0.18은 API가 달라 검증하지 못함). 공유 상태는 Schema가 아니라 메시지 기반 델타 스냅샷입니다(트래픽 최소화·단순함 목적).
- 16명은 **프로토콜/서버 부하**만 검증했습니다. 16개의 실제 브라우저 렌더링 부하는 테스트하지 못했습니다(아바타는 드로우콜 ~7개/명으로 설계).
- 상호작용 건물은 문 앞 안내만 있고 **내부 공간이 없습니다.** 낮/밤 전환, 오디오, 의상 교체 없음.
- 서버는 `tsx`로 직접 실행합니다(별도 빌드/컨테이너/배포 설정 없음). 인증·계정·방 비밀번호·신고/차단·채팅 없음(게스트 전용). 닉네임 필터링은 제어문자/마크업 제거와 길이 제한까지만입니다.
- `npm audit`가 의존성 취약점 3건(보통 2, 높음 1)을 보고합니다(`@colyseus/ws-transport` 경로 포함). 개발 의존성 포함 여부와 영향은 평가하지 않았습니다.
- 알려진 시각 개선점: 광장 돌바닥이 다소 단조로움, 남쪽은 넓은 눈밭(포토 가든 예정 부지), 트리 가지는 여전히 약간 각진 느낌(가지 단 수/세그먼트 증가로 개선 가능).

## 다음 단계 제안 (Phase 4–5)

1. **모바일 성능**: 지오메트리 LOD/거리 컬링, 건물 단위 병합 정책 재조정, 텍스처 아틀라스, 실기 프로파일링. 2. 낮/밤 전환(조명 `SKY`/라이트 값을 한 곳으로 모아 둠). 3. 볼룸·소원 숲·마켓: `ZONES`/`Interactable`/`emit("interact")`에 기능 모듈을 붙이고, 공유 상태가 필요하면 룸 메시지 또는 Schema 추가. 4. 아바타 외형 슬롯(`AvatarSpec`)과 서버 동기화 필드 확장. 5. 포토부스는 동의·보관/삭제 정책·서버측 키·호출 제한부터 설계. 6. 배포(서버 컨테이너, HTTPS/WSS, 다중 프로세스 시 Redis presence).
